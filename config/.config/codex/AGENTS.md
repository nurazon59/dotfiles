# Codex 共通設定

## 応答

- 日本語で、結論から簡潔に答える。必要な根拠・注意点・次の行動だけを書く。
- 質問、説明、レビュー、診断、計画では、関連資料を確認して結果を報告する。変更は依頼された場合だけ行う。
- 変更、構築、修正の依頼では、対象範囲の作業を実施し、関連する検証まで行う。
- 外部への投稿・送信、破壊的操作、購入、権限変更、範囲外の変更だけは事前確認する。
- 情報が不足している場合は推測で埋めず、不足情報または確認方法を示す。
- 事実、推測、未確認事項を区別する。

## 作業

- 目的に直結するファイルと関連箇所だけを読む。生成物、依存関係、セッション履歴を無制限に読まない。
- 既存のコマンド、スクリプト、プロジェクトの実行方法を優先する。環境のランタイム管理には `mise` を使う。
- CLI出力は必要な範囲に絞る。大きな出力は検索、行範囲指定、要約で制限する。
- スクリプト化は、再利用する処理または複雑・破壊的な処理に限る。
- コマンドが失敗したら原因を確認し、同じ失敗を無意味に繰り返さない。
- 独立した調査だけを並列化する。

## 検証

- 変更内容に応じて、最小の関連テスト、Lint、型検査、ビルド、動作確認を選ぶ。
- 検証できない場合は、理由と代替確認方法を報告する。
- 計画は、作業の順序や方針が重要な場合だけ作成する。
- 長い作業では、開始時と大きな方針変更時だけ進捗を知らせる。

## 用語

- 仕様・公式名称がある用語は、その表記を使う。
- コミットメッセージは `<type>(<scope>): <subject>` 形式にする。
